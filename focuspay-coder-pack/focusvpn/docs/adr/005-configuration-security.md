# ADR-005: Безопасность конфигураций (подпись + версионирование)

- **Статус:** Принято (PHASE 1, 10.08.2026)
- **Дата:** 10.08.2026
- **Основа:** `docs/ARCHITECTURE.md` §8; `docs/SECURITY.md` §4; `docs/API.md` §7

## Контекст

VPN-клиент получает конфигурацию из Control Plane через REST. Конфигурация содержит параметры
интерфейса, серверный публичный ключ, эндпоинт, параметры обфускации — критична для корректного и
безопасного подключения. Нужно защитить от подмены (MITM на пути к клиенту), replay (устаревший
конфиг) и утечки приватных данных.

## Решение

- CP подписывает содержимое конфигурации ключом **Ed25519** (`config_signing_key`, хранится в
  KMS/HSM). Подпись идёт в ответе `GET /v1/configurations/:id`.
- У конфигурации есть **`config_version`** (монотонно растёт); клиент отклоняет версию ниже
  кэшированной (защита от replay).
- **Приватный ключ клиента не передаётся и не хранится в CP** — генерируется/хранится в secure
  storage устройства; клиент вставляет его в конфиг локально.
- Секретные «части» (REALITY uuid/shortId, server key) в БД хранятся зашифрованными
  (envelope encryption, AES-256-GCM под DEK из KMS), см. SECURITY.md §4.2.
- Отзыв: `status=revoked`, инкремент версии; fetch отозванного → `410 Gone`.
- Ротация ключей: новая пара клиента + перевыпуск конфига (rotate-key), серверные ключи — ротация
  с перекрытием окна.

## Последствия

**Плюсы:** защита от подмены конфига (подпись), от replay (version), от утечки приватного ключа
клиента (не покидает устройство), возможность полной отзывной ротации.

**Минусы:** нужно раздать клиентам публичный ключ CP (зашит в приложение), обрабатывать 410 и
version conflicts на клиенте; envelope-шифрование добавляет слой управления ключами.

## Альтернативы

- Конфиг без подписи (только TLS) — отклонено: TLS не защищает от MITM-прокси и кэша.
- JWT вместо подписи Ed25519 — избыточно (не нужна expiry в конфиге; версия закрывает вопрос).
- Хранить приватные ключи клиентов в CP и выдавать готовый конфиг — отклонено (компрометация CP
  = компрометация всех клиентов).
