# ADR-004: Node Agent и связь с Control Plane

- **Статус:** Принято (PHASE 1, 10.08.2026)
- **Дата:** 10.08.2026
- **Основа:** `docs/ARCHITECTURE.md` §5; `docs/API.md` §11; `docs/DEPLOYMENT.md` §2

## Контекст

Нужен способ управлять VPN-нодами: провижинить, применять peer-таблицы, конфигурировать движки
(AmneziaWG/WG/REALITY), собирать health/telemetry, поддерживать ротацию ключей. Сеть: ноды в разных
юрисдикциях, за NAT и файрволами; контрольный трафик должен быть двусторонним.

## Решение

- На ноде — **Node Agent** (Go, отдельный процесс): управляет VPN-интерфейсами/процессами,
  применяет состояние из CP, собирает метрики.
- Связь: **poll-модель + mTLS**:
  - mTLS (внутренний CA): агент при первом старте регистрируется одноразовым `node_token`
    (`POST /v1/agent/register`, передаёт CSR, получает сертификат на 90 дней с автопродлением);
  - агент делает **long-poll** `GET /v1/agent/state?since=version` с таймаутом **30 s**;
    после ответа (включая empty/timeout) — повтор через **≤5 s**; CP через Redis pub/sub
    может разбудить ожидающий poll немедленно после изменения desired state;
  - при конфликте — `409 stale_version` → полная пересинхронизация (`since=0`);
  - агент шлёт `POST /v1/agent/telemetry` (load, rx/tx, peer_count, состояние эндпоинтов)
    каждые **15–30 s**.
- Применение AmneziaWG на ноде: subprocess **`awg`** / `awg-quick` (GPL tools) — не линковать
  GPL в agent binary; см. ADR-002 и DECISIONS.md.
- Control Plane не держит постоянные соединения к нодам (не нужно открывать входящие порты к нодам
  из интернета — только исходящие от агента).
- Вся конфиденциальность в канале: mTLS; приватные ключи движков живут только на ноде.

## Последствия

**Плюсы:** простота (без push-инфраструктуры), безопасная модель (исходящие соединения от агента),
согласованное состояние через версионирование, не зависит от NAT/провайдера.

**Минусы:** задержка применения изменений ограничена long-poll (до ~30 s без Redis wake;
с wake — почти сразу); при падении CP нода продолжает работать с последним применённым состоянием.

## Альтернативы

- Long-lived push/websocket от CP к ноде — отклонено: требует входящих портов к нодам и keepalive.
- Без агента (только SSH+скрипты) — отклонено: нет согласованного состояния и метрик.
- Очередь сообщений (NATS/Kafka) — избыточно на старте; можно добавить позже поверх poll.
