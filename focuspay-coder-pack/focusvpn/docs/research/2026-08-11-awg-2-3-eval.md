## Summary

Upstream splits generations clearly. **Product docs** call out AWG **1.5** (UDP mimicry), **2.0** (dynamic H1–H4 ranges, S1–S4 padding on all message types, I1–I5 CPS signature packets + junk train Jc/Jmin/Jmax), and **3.0** (extra anti-statistical measures after mid-2026 RU blocks; self-hosted install still rolling out; HeaderProtectionKey, ContentPaddingAddition, tunable rekey/keepalive ranges in go README).

**Go tags:** latest classic line remains **`v0.2.19`**; newest line is **`v3.0.20260805`**. The v3 tag is a **new Go module path** (`…/amneziawg-go/v3`), not a semver bump on the same import — clients and AppCore cannot “just update the version string.”

**Compatibility:** Amnezia’s 2.0 blog states prior protocol versions are **not compatible** with 2.0; fresh guest configs required; legacy stays as “AmneziaWG Legacy.” Docs list 2.0 params: I1–I5, S1–S4, Jc, Jmin/Jmax, H1–H4 (non-overlapping H ranges). With all obfuscation zeroed, behavior falls back toward plain WireGuard.

**What `v0.2.19` already exposes:** Jc/Jmin/Jmax, S1–S4, H1–H4, I1–I5 (per that tag’s README). **P4-M8** ships H/S/I in ConfigParts / seeds / clients (I1–I5 optional) while staying on this pin — see [[plans/P4]], [[API]], [[DATABASE]].

**AWG 3.0 extras (v3 README only):** `HeaderProtectionKey` (server-side; needs S1–S4 ≥ 12), `ContentPaddingAddition`, timing knobs (`RekeyAfterTime`, `RekeyTimeout`, …) with **range** syntax. Docs say fuller 3.0 self-hosted write-up lands after AmneziaVPN can install it on user servers.

## Relevance to FocusVPN

| Option | Effort | Risk if skipped |
|---|---|---|
| **Stay on `v0.2.19` + Jc/Jmin/Jmax** (current) | None | DPI may fingerprint junk-only AWG in hard nets |
| **Enable H/S/I on same pin** (schema + node uniqueness) | Medium — API/DB/ConfigParts/UAPI/clients/agent; no module rewrite | Still not full 2.0 product profile / CPS defaults |
| **Jump to `amneziawg-go/v3`** | High — module path, Go 1.25+, tools on nodes, Android/Apple bridges, ADR, dual-fleet or hard cut | Needed only if 2.0-on-0.2.19 fails under measured DPI |

**Decision (this eval):** keep MVP pin **`v0.2.19`**. Do **not** migrate to `v3.0.*` without a dedicated ADR and coordinated rollout. Optional later milestone: extend obfuscation JSON with H/S/I (still on v0.2.19) if Xray/REALITY + Jc-only AmneziaWG prove insufficient. Trigger for revisit: field DPI evidence, or Amnezia self-hosted 3.0 becoming the only maintained peer path for our node OS.

## Migration checklist (if ADR later)

1. ADR superseding pin in [[002-vpn-engine-strategy]] / [[OPEN_SOURCE]]
2. Expand `protocol.obfuscation` (+ node uniqueness rules for H ranges / CPS)
3. AppCore UAPI + Android/Apple formatters + node-agent `awg` apply
4. Replace `go.mod` require with `…/amneziawg-go/v3` (or stay on 0.2.19 with H/S/I only)
5. Rebuild `libwg-go.so` / WireGuardKitGo against chosen tag
6. Fleet: dual protocol or forced client min-version
