# FocusPay

FocusPay — сервис криптообмена: публичный сайт, личные кабинеты, админ- и операторская панели, FastAPI API и Telegram-бот. Репозиторий содержит взаимосвязанные production-компоненты. Здесь работают реальные пользователи и сотрудники, поэтому безопасность и проверка контракта важнее скорости изменений.

> **Начинаете работу?** Сначала прочитайте [`AGENTS.md`](AGENTS.md), затем [`docs/DEVELOPER_ONBOARDING.md`](docs/DEVELOPER_ONBOARDING.md). Второй документ — практическая карта проекта, потоков данных и безопасной разработки.

## Карта проекта

| Путь | Назначение | Статус |
|---|---|---|
| [`focussite/frontend/`](focussite/frontend/) | Активный React-фронтенд: публичный сайт, `/x8` для админов и `/ops` для операторов | Рабочая область фронтенд-задач |
| [`site/exchange-backend/`](site/exchange-backend/) | FastAPI API, бизнес-правила, авторизация, SQL-миграции и интеграции | Источник API-контрактов; изменять только с явным согласием |
| [`bot/tg_bot_btc/`](bot/tg_bot_btc/) | Production Telegram-бот, Payfast webhook и операционные уведомления | Рабочая область задач бота, требующая повышенной осторожности |
| [`docs/`](docs/) | RBAC, замороженные зоны, интеграции, архитектурные решения и runbook’и | Читать перед изменением соответствующей области |
| [`focussite/`](focussite/) | Локальный Docker-стенд и контейнерная инфраструктура | Только локальная разработка; см. [`DOCKER_LOCAL.md`](focussite/DOCKER_LOCAL.md) |
| [`focus-panel/`](focus-panel/) | Исторический Vue-макет панели | Только визуальный референс, не production-код |

`site/focuspay.org/`, упоминаемый в части старых материалов как скомпилированный legacy-сайт, в текущей рабочей копии отсутствует. Не опирайтесь на него как на доступный источник реализации.

## Быстрый безопасный старт

1. Проверьте незавершённую работу коллег: `git status --short`. Не смешивайте свою задачу с чужим WIP.
2. Прочитайте правила: [`AGENTS.md`](AGENTS.md), [`docs/FROZEN.md`](docs/FROZEN.md) и, для панели, [`docs/PERMISSION_MATRIX.md`](docs/PERMISSION_MATRIX.md).
3. Выберите поверхность задачи и найдите маршрут/обработчик в onboarding-документе.
4. Перед фронтенд-изменением прочитайте API-роутер в `site/exchange-backend/routers/`: поле ответа и право доступа нельзя угадывать.
5. Перед отчётом выполните релевантную проверку. Базовый набор команд приведён в [onboarding](docs/DEVELOPER_ONBOARDING.md#проверки).

## Критические ограничения

- Не коммитить, не пушить и не деплоить без явной просьбы.
- Не раскрывать и не записывать секреты: `.env`, токены, пароли, ключи HMAC/JWT и DSN.
- Не обходить JWT, 2FA, RBAC, CAPTCHA, IP allowlist и другие защитные механизмы.
- Не менять финансовые формулы, переходы статусов заявок, Payfast/HMAC, SQL-миграции, сетевой периметр или systemd/nginx без отдельного согласования.
- Dev-сервер фронтенда по умолчанию проксирует `/api` на `https://focuspay.org`; работайте с боевыми данными только осознанно.
