# Диагностика приёма — реализация 15 сентября 2026

## Принятый план

1. Готовность реквизита, факты назначения и статистика потока отображаются отдельно.
2. Прогноз использует 35 полных исторических интервалов по местному времени МСК. Сначала пять соответствующих дней недели; при числе подходящих событий меньше восьми — все 35 дней. Интервалы без заявок входят в знаменатель. Вероятность — доля интервалов с хотя бы одной подходящей заявкой за 15/30/60 минут.
3. orders.created_at трактуется как UTC без timezone и переводится в МСК в Python. OP-заявки и неизвестные способы оплаты исключены. CARDRUB может попадать на СБП, как в подборе. Фильтр криптовалюты не добавлен: reserve_payin_slot её не принимает.
4. Суммы проверяются существующим fit_payin; последовательности закрытия проверяются по остатку и лимиту, без изменения механизма выдачи. Последовательности — примеры, а не прогноз времени оплаты. Они предполагают последовательное подтверждение без ожидания и конкуренции.
5. История покупателя на момент попытки, несозданные заявки, конкуренция реквизитов и согласие на округление не восстановлены. Оценка показывает потенциальный поток, не шанс фактического назначения этой карте. Доля оплат рассчитана только среди завершённых заявок.

## Интерфейс и API

На выбранном собственном payin-реквизите в подробностях показывается «Прогноз и диагностика». Отображаются причины недоступности, факт назначения (не доставки Telegram), суммы, частоты 15/30/60 минут, конверсия и примеры закрытия.

GET /operator/payout-requisites/{id} содержит diagnostics только для владельца. GET /operator/payout-requisites/{id}/plan для payin возвращает kind=diagnostics и diagnostics. Выплатный план не изменён. История запросов к БД кешируется в процессе на 60 секунд, текущие назначения читаются заново. Ошибка диагностики в detail возвращает unavailable, не нулевую статистику. Миграций и новых журналов нет.

## Проверки

- 12 новых тестов: UTC/МСК, полночь, пустая история, нулевые интервалы, выбор дня недели, метод оплаты, 5/10/20 тысяч, лимит, резерв, ошибки связей.
- 61 backend-тест прошёл; один ранее несовместимый тест буквальных старых подписей исключён.
- npm run build прошёл, предупреждение о размере bundle.
- Изолированный Playwright smoke прошёл: диагностика без назначений, открытие подробностей, актуализация чека, отмена, недоступность данных, форма, включение и права. Все API перехватываются, живые финансовые операции не вызываются.
- Обезличенные данные прода загружены read-only: 1594 BUY с известным методом и без OP за окно 36 дней; используются 35 сравнительных интервалов. Расчёт выполнен на них локально. Это техническая проверка на реальной выборке, не независимая проверка точности прогноза. Ретроспективная калибровка и полный staging цикл остаются перед выпуском.
