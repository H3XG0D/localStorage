# Review 2026-08-17

## TL;DR

• **Ops темп высокий** (4 крупных блока 12.08), но критичные задачи теряются в Backlog без owner — нужен еженедельный триаж P1/P0 с жёсткими дедлайнами

• **Security блокирует prod**: 5 критичных OWASP (guest cookie leak, finance ACL, webhook без IP-whitelist) + секреты без ротации — приоритет на 48 ч, иначе риск эксплойта платежей

• **Offsite backup не настроен** — при взломе/пожаре хоста бэкапы теряются вместе с сервером, recovery невозможен

• **FocusPay P&L пустой**: капитал, топапы, комиссии не зафиксированы — нет visibility, горит проект или приносит деньги; снять snapshot на этой неделе

• **Ручная работа съедает время**: Telegram → Day notes, финучёт, TODO sync между досками — 4 quick wins (ledger-команда в боте, TODO-скрипт, P&L dashboard) дадут 5–7 ч/неделю

• **MYVPN запуск заблокирован**: FR dedic не заказан, VPN-бот не задеплоен, зависимость от фикса OWASP — следующий шаг: PAR-SM5038 + токены + smoke-тест федерации

• **Tone-риск**: неформальные фразы во внутренних чатах могут утечь клиентам через forward — разделить каналы (ops-internal vs ops-tickets)

## ProductAuditor

## ProductAuditor

### Риски

1. **OWASP P1 открыты — Ready for Production: No**  
   Аудит от 12.08 выявил критические уязвимости (A01 Broken Access Control, A03 Injection, A05 Security Misconfiguration, A07 Auth failures). В проде без фикса: guest cookie leak, finance ACL для admin/ops, отсутствие captcha, referral html.escape. Каждый P1 — потенциальная дыра для несанкционированного доступа к финансам или утечки данных.

2. **Payfast webhook без IP-whitelist**  
   `WEBHOOK_ALLOWED_IPS` не задан, `REQUIRE=1` отключён — любой может слать фейковые колбэки на `/api/payfast/webhook`, провоцируя ложные зачисления или обход лимитов. Freeze на Payfast блокирует быстрый фикс без approve.

3. **Секреты в `.env` + возможная утечка Lelouch/bot token**  
   Если токены светились в логах/чатах/репо, злоумышленник может выдавать себя за бота или админа. Ротация не сделана.

4. **Offsite backup не настроен**  
   `OFFSITE_RSYNC` не прописан в `/etc/focuspay/backup.env` — при пожаре/взломе хоста бэкапы теряются вместе с сервером. Recovery невозможен.

5. **Freeze-зоны сковывают реакцию на инциденты**  
   Финансовая логика и Payfast заморожены — если придёт эксплойт на формулу комиссии или webhook, исправить нельзя без длинного согласования (правило агента требует approve).

---

### Долг

1. **OWASP P1 ждут фикса с 12.08**  
   Пять дефектов в безопасности (ACL, captcha, escape, guest cookie, webhook IP) — каждый требует патча + регресс-тесты. Накопление критических CVE снижает доверие к платформе.

2. **tg_bot_btc без VCS**  
   Бот не в git, нет истории изменений — при откате/регрессии восстановить предыдущее состояние невозможно. Риск потери кода при краше диска.

3. **Калькулятор buy: регресс-кейсы недостаточны**  
   Баг «0.5673 LTC» поймали только в проде (отчёт Ops AI #1). Тесты `test_buy_amount_contract.py` добавлены постфактум — нужна матрица граничных значений (round, markup, fallback курса).

4. **Multi-agent Ops AI findings не автофиксятся**  
   `/x8/ai-tasks` показывает результаты triage/security/ui/backend агентов, но исправления идут вручную. Цикл «найти → создать таску → исправить → проверить» медленный.

5. **Self-check (focuspay-selfcheck) не эксплойт-тест**  
   Smoke + auth walls каждые 15 мин, SAST nightly — полезно, но не покрывает payloads (SQL injection, XSS, CSRF). Реальный pentest нужен отдельно.

6. **Ревизия функций бота не сделана**  
   «Что просело, что докрутить» в backlog, но не оценено. UX-просадки (долгие ответы, неясные ошибки, отсутствие retry) могут снизить конверсию.

## FinanceWatch

### Учёт

**Личный ledger:** записи есть (11–12.08: ~34 USD экспенсов). **FocusPay-PnL:** пустая таблица — ни капитала, ни топапов, ни комиссий.

### FocusPay капитал / topup / pnl

**Дыра:** обменник в проде (активные сделки, ops-отчёты, аудит), а в `FocusPay-PnL` — три пустые строки. Не зафиксировано:

- сколько капитала «внутри» (крипта + фиат в резерве);
- сколько докинуто с личных средств;
- накопленная комиссия / прибыль.

**Проблема:** без этих данных невозможно считать burn (личные экспенсы vs доход с бизнеса), ROI, или понять, окупается ли проект.

### Что зафиксировать на этой неделе

1. **Снять snapshot капитала** — вручную через бота или SQL к проду: баланс кошельков (BTC/USDT/LTC/TRX) + фиатный резерв. Записать в `FocusPay-PnL` оценку «капитала внутри».
2. **Вспомнить и записать все топапы** — если докидывал крипту или фиат в обменник, внести суммы построчно (`topup | amount | currency | note`).
3. **Выгрузить комиссии за период** — либо из дэшборда, либо SQL `SELECT SUM(...)` по заказам со статусом PAID; записать накопленную прибыль (`pnl | amount | RUB | "комиссии 01.08–12.08"`).
4. **Завести привычку:** еженедельно (например, воскресенье) — одна строка в P&L с комиссиями за неделю + snapshot капитала в примечании.

**Итог:** пока P&L пустой, нет visibility — горит проект или приносит деньги.
