# Review 2026-08-19

## TL;DR

• **Безопасность блокирует продакшн**: OWASP P1 открыты (webhook без IP whitelist, finance ACL дыры, guest cookie риск), секреты могли светиться, offsite backup не настроен — критично зафиксить за 2 дня

• **Финансовый учёт сломан**: FocusPay P&L пустой (нет данных по капиталу, topup, комиссиям), личный Ledger показывает ~$500/мес burn, но экономика проекта непрозрачна — нужна срочная инвентаризация

• **Интеграция MYVPN застряла**: FR dedic не заказан, control plane не развёрнут, federation API заблокирован незафикшенным OWASP — следующий шаг заказать хост + создать скелет VPN-бота

• **Операторский срез отсутствует**: нет данных по сменам, времени ответа, закрытым тикетам #focuspay-ops — оценить работу команды невозможно, нужен дамп за 7–14 дней

• **Техдолг нарастает**: tg_bot_btc не в VCS (откат невозможен), Processing/INDEX заброшен, ручной копипаст из Telegram в Days съедает время — есть quick wins (inbox bot, Ledger inline, OWASP alert за 1–2 дня)

• **Приоритет на завтра**: webhook IP whitelist + offsite rsync (день 1), ротация секретов + OWASP P1 guest/finance fix (день 2), git init для бота — остальное после стабилизации security

## ProductAuditor

## Риски

**Критические:**
- **OWASP P1 открыты** — продакшн не готов по аудиту (A01–A07/A09 Fail). Guest cookie, finance ACL для admin/ops, отсутствие captcha, html.escape в referral. Ставит под удар финансы и пользовательские данные.
- **Webhook без IP whitelist** — Payfast callback не проверяет источник (`WEBHOOK_ALLOWED_IPS` + `REQUIRE=1` отсутствуют). Любой может слать липовые уведомления о платежах.
- **Секреты могли светиться** — root-пароль, Lelouch токен, bot token. Если утечка была — доступ к серверу и боту открыт.
- **Offsite backup не прописан** — `OFFSITE_RSYNC` в `/etc/focuspay/backup.env` пуст. При пожаре на хосте данные теряются.

**Средние:**
- Freeze-зоны работают как защита, но замедляют развитие финансовых фич. Если нужно быстро реагировать на инцидент в `order_financial.py` — нужен approve на разморозку.
- Калькулятор BUY чинили post factum (0.5673 LTC кейс) — regression tests есть, но incident response показал уязвимость в курсах без fallback.

## Долг

**Технический:**
- **git init + remote для tg_bot_btc** — бот не в VCS, откатить изменения или сравнить версии нельзя. Ручная синхронизация с продом через rsync рискованна.
- **Ревизия функций бота** — что просело, что докрутить. После multi-agent Ops AI и self-check нужен аудит UX/conversion: какие флоу бросают, где падают пользователи.
- **Security scan CI** — есть `scripts/security_scan.sh`, но не ясно, запускается ли он автоматически перед деплоем.

**Процессный:**
- **Ротация секретов** — план есть (`SECURITY.md`), но не выполнен. Без чеклиста «что ротировать и как» можно пропустить токен.
- **Offsite backups** — инфраструктура (`focuspay-backup-offsite` упомянут в CURRENT), но env не заполнен.

**Документация:**
- Ops AI, OPS_AI_MULTI_AGENT, self-check задокументированы ([[OPS_AI]]), но нет run-book для оператора при пожаре (что делать, если self-check нашёл exploit attempt).

### Паттерны ручной работы

**Days → кружочки/сообщения**  
Ежедневные файлы (`Day 2026-08-XX`) заполняются вручную: временные метки, цитаты из Telegram, ссылки на кружки. Структура повторяется — секция "Активность", секция "Кружочки" (всегда пустая), копипаст текста из чатов. День 2026-08-11 содержит 30+ сообщений из канала "Админ отчеты" с метками времени.

**Processing/INDEX → пустая таблица**  
Индекс пересылок создан, но не используется — таблица без записей. Судя по описанию, туда должны попадать офферы, переписки, процессинг — но процесс не автоматизирован, поэтому заброшен.

**Finance/Ledger → ручные записи расходов**  
Каждая трата (продукты, услуги) вносится строкой вручную. Формат строгий, но заполнение manual. FocusPay-PnL вообще требует "вручную через бота, пока без SQL к проду" — таблицы "Капитал", "Докинуто", "Комиссии" пустые.

**Telegram bind + digest (свежедобавленное)**  
В CURRENT упомянута новая фича "Telegram дайджест" (focuspay-ops-ai-digest) — но это именно то, что *решает* проблему ручного сбора отчётов. Значит, до 12.08 операторы собирали сводки вручную.

### Идеи автоматизации (effort S/M/L)

**1. Telegram → Days autoparser (M)**  
Webhook/long-poll бот, который слушает целевые каналы (Админ отчеты, личные чаты) и автоматически:
- Создаёт/обновляет `Day YYYY-MM-DD.md` с timestamp + sender + текст.
- Складывает кружки в `Life/Circles/` и линкует.
- Фильтрует шум (стикеры, реакции).

**Quick win:** даже без LLM — просто structured append в markdown. Убирает 100% копипаста из Telegram.

**2. Processing inbox bot (S)**  
Telegram-команда `/process <тема>` → бот форвардит сообщение + апдейтит таблицу в `Processing/INDEX.md` (дата, тема, ссылка на файл). Или автоматом складывает форварды из специального канала.

**Quick win:** INDEX заполняется сам, поиск по пересылкам работает.

**3. Finance Ledger via Telegram inline (S)**  
Команда `/spend 514 THB Grab продукты` → бот парсит, добавляет строку в `Finance/Ledger.md` через API/git commit. То же для `/topup`, `/pnl`.

**Quick win:** записи расходов не теряются, не нужно открывать файл.

**4. FocusPay P&L SQL-дашборд → auto-sync (L)**  
Вместо "вручную через бота" — cron-скрипт на сервере читает `ORDER`, `CASHBACK`, `REFERRAL` таблицы, считает капитал/комиссии/докиды и пушит summary в `FocusPay-PnL.md` (или отдельный `snapshot.json`). Ops AI может читать это для отчётов.

**Effort L** (нужен SQL-доступ, безопасные credentials, тесты), но полностью убирает manual reconciliation.

**5. OWASP/Security fix tracker (S)**  
`TODO.md` содержит чеклист "Fix OWASP P1". Скрипт парсит отчёт `SECURITY_AUDIT_OWASP_20260812`, генерирует GitHub Issues (или строки TODO с датами/assignee), синкает статус обратно. Алерт в Telegram, если P1 открыт >3 дня.

**Quick win:** безопасность не забывается, дедлайны прозрачны.

### Quick wins

| Автоматизация | Effort | Impact | Реализация |
|---|---|---|---|
| **Processing inbox bot** | S | High | Telegram bot + markdown append API; `/process` добавляет строку в INDEX |
| **Finance Ledger inline** | S | Medium | `/spend` / `/income` команды → git commit или HTTP API к vault |
| **OWASP alert** | S | High | cron парсит отчёт, шлёт в TG если P1 не зафикшен за N дней |
| **Telegram → Days parser** | M | High | Webhook бот + темплейт; автозапись активности, убирает весь копипаст |

**Рекомендация начать с #2 (Processing) и #3 (Finance)** — минимальный код, мгновенная польза, не требуют доступа к продовой БД.

### FocusPay капитал / topup / pnl

**Дыра**: таблица сводки и журнал — нулевые. Непонятно:
- Сколько капитала «внутри» обменника (оборотка на кошельках)?

- Какие комиссии собраны с запуска?

**Topup vs pnl**: разделение не ведётся. Если капитал докидывался — нет следа; если прибыль уже фиксировалась — не записано.

### Что зафиксировать на этой неделе

1. **Инвентаризация** — снять балансы BTC/USDT/LTC/TRX кошельков обменника → записать как «капитал внутри» (₽ по текущему курсу).
2. **Topup** — если были переводы со своих адресов на рабочие кошельки FocusPay, зафиксировать сумму и дату.
3. **Комиссии** — вытащить из проды (SQL или через бота) накопленную прибыль по сделкам → записать в pnl.
4. **Личные расходы** — продолжить Ledger; сейчас ~$33 за 2 дня, следить за динамикой.

**Критично**: без FocusPay-PnL непонятна экономика проекта (ROI, точка безубытка, нужен ли ещё topup).
