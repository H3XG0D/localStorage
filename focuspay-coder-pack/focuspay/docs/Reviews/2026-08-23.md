# Review 2026-08-23

## TL;DR

# Резюме для босса

• **Ops в норме, но медленно**: автоматизация (AI-память, дайджест, триаж) работает, но фиксы идут долго и без clear SLA. P1 security задачи (OWASP) лежат в Backlog без assign. Рекомендация: SLA по P1 + регресс-тесты в CI перед любым деплоем на финансы.

• **Критич: 6 OWASP фейлов блокируют продакшн** — guest cookie утечка, финансовые ACL дыры, слабая защита от brute-force, XSS в операторчате. Fix-план не начат. Дедлайн: 14.08 EOD. Без фиксов нельзя выводить в более широкую публику.

• **Секреты под угрозой** — нужна срочная ротация root-пароля, bot-токена, Lelouch-токена (возможна утечка в логах). Offsite бэкапы не настроены. Риск полной потери данных. Дедлайн: 13.08 EOD.

• **Финансовая слепота**: PnL FocusPay не заполняется, неизвестен капитал в кошельках, нет учета комиссий и затрат. Бот работает в проде с 12.08, но ни одного числа по доходу. До 15.08 нужны снимки баланса и сводка сделок.

• **MYVPN-интеграция заморожена** — ждёт фиксов OWASP и ротации секретов. Разморозка на финансовые домены требует явного approve. После чистки будут вебхуки + управление юзерами.

• **Автоматизация ждёт**: secret rotation (Vault + cron), security findings → alerts в Telegram, auto-index для ежедневных отчётов. Quick wins за 1–2 дня спасают 2–3 часа/неделю.

• **Ситуация управляемая, но требует действий СЕЙЧАС**: P0 — OWASP fix + ротация секретов (до 14.08), P1 — финансовый учёт (до 15.08). Затем интеграция откроется.

## OpsReviewer

### Сильное

- **Память Ops AI** — фиксируются инсайты по людям (ops_ai_memories) и привязка Telegram (opsbind_). Операторы лучше ориентируются в истории/паттернах.
- **Ежедневный дайджест** (focuspay-ops-ai-digest) — централизованный срез за день уменьшает дублирование вопросов.
- **Multi-agent триаж** (create_dev_task) — автоматическое распределение по security/ui/backend снижает незапланированные эскалации.
- **Self-check каждые 15 мин** — дымовые тесты + nightly SAST ловят инциденты до жалоб клиентов (как с 503 курсов 12.08).
- **Шаблоны + RBAC** — единые ответы и разграничение доступа убирают путаницу в shift-ах.

### Слабые места

- **Скорость фиксов** — ошибка курса (503) и округления fiat дошла до проде; операторы сообщили («калькулятор наебнулся»), но проверка не была про-active. Нет метрики MTTF (Mean Time To Fix).
- **Эскалация P1 security** — OWASP audit показал 6 фейлов (guest cookie, finance ACL, captcha escape), но tasks сидят в Backlog; неясен приоритет.
- **Смены без clear handoff** — нет очевидного protocol, как передать контекст между shift-ами; ops_ai_memories помогает, но `#focuspay-ops` нужна синхро.
- **Freeze-зоны недокоммуникированы** — `.cursor/rules` + CLAUDE §10 + список файлов могут быть проигнорированы, если оператор не знает фраз типа «можно трогать финансы».

### Рекомендации

1. **Завести SLA по P1** — OWASP fix-план в работу до конца недели; вывесить доску `[[FocusPay Board]]` с явной колонкой «Security P1» и own-ер на каждый task. Еженедельный review на standup.

2. **Regress-gate перед deploy** — при любом изменении financial_* / buy_payout_* запускать `tests/test_financial_safety.py` + `tests/test_buy_amount_contract.py` в CI; блокировать merge без зелёного статуса. Добавить MTTF-метрику в лог.

3. **Ops onboarding: Freeze-зоны as checklist** — перед first shift новый operator подписывает что-то вроде «Я прочитал [[FROZEN]] и понимаю, что не трогаю order_financial/buy_payout без OK». Telegram reminder каждый понедельник в `#focuspay-ops`.

## ProductAuditor

## ProductAuditor — Отчёт по FocusPay

### Риски

1. **OWASP P1 открыты (Ready: No)** — Security Audit от 12.08 вернул fail по A01–A07, A09. Конкретно:
   - Guest cookie утечка (сессия в localStorage видна гостям)
   - Finance ACL: admin/ops-пользователи видят чужие платежи без gate
   - Captcha/brute-force: слабая защита на login (есть autoban, но нет rate-limiting фронта)
   - HTML escape: шаблоны в операторчате не экранируются → XSS на бот-сообщения
   - Это **блокирует** продакшн без фиксов.

2. **Секреты в .env, возможная утечка** — требуется немедленная ротация root-пароля, Lelouch-токена, bot-токена (если светились в логах/чатах). Без ротации любой breach.

3. **Offsite бэкапы не настроены** — `OFFSITE_RSYNC` не прописан в `/etc/focuspay/backup.env`. При инциденте на основной ноде данные теряются.

4. **FROZEN-зоны хорошо обозначены, но интеграция MYVPN требует разморозки Payfast** — нужен explicit approve перед любыми правками в `services/buy_payout.py`, `services/commission.py`.

### Долг

1. **Fix-план по OWASP P1 не начат** — стоит в TODO, но нет assign + timeline. Должен быть:
   - Guest cookie → `httpOnly=True + Secure` или JWT instead
   - Finance ACL → Row-level filtering в `operator_external` ACL (уже есть spec, нужна реализация)
   - Captcha → интегрировать hCaptcha или Yandex
   - HTML escape → `markupsafe.escape()` во все шаблоны + ESLint rule

2. **Webhook security**: `WEBHOOK_ALLOWED_IPS` не установлены для Payfast. Каждый мог бы спуфировать webhook → поддельный платёж. Срок 13.08 по плану.

3. **Ops-функции не ревизированы** — TODO: «ревизия функций бота: что просело, что докрутить». Нет списка багов/деградации после выката multi-agent.

4. **git init для `tg_bot_btc` не сделан** — repo в приватный remote не поднялся, нет версионирования бота.

5. **Интеграция MYVPN отложена** — требует разморозки financial/Payfast, но approve-документ не готов (нужен `CLAUDE.md` update).

## EcosystemLink

### EcosystemLink

#### Блокеры интеграции
Интеграция между FocusPay и MYVPN все еще сталкивается с определенными проблемами, которые требуют решения. Основные блокеры на данный момент:
1. **Безопасность**: Поддержание OWASP безопасности на высоком уровне с открытыми P1 проблемами в FocusPay.
2. **Ротация секретов**: Убедиться, что все секреты, хранящиеся в `.env`, проходят ротацию при любой утечке.
3. **Freeze домены**: Текущий статус frozen для денежных операций и Payfast.

#### Следующий маленький шаг
Следующий шаг в интеграции — настройка вебхуков для синхронизации данных пользователей между FocusPay и MYVPN. Необходимо также реализовать систему пополнения баланса для VPN-бота через FocusPay. Это включает в себя:
- Установление правил для IP-адресов, с которых могут приходить запросы.
- Аудит прав доступа и централизованная база данных пользователей.

#### Зависимости от команды
Для успешной реализации интеграции команду ждут следующие действия:
- Завершить работу по исправлению P1 проблем безопасности в FocusPay.
- Провести окончательный аудит и тестирование интеграции, включая проверку на ошибки и уязвимости.
- Обеспечить доступность и работоспособность API как в FocusPay, так и в MYVPN для корректного взаимодействия.
- Подготовить и задеплоить нового Telegram-бота для управления пользователями и пополнениями.
