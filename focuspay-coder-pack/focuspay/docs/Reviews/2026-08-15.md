# Review 2026-08-15

## TL;DR

**Сводка по ролям — критичное**

• **Безопасность в проде: P1 открыты** — guest cookie hijack, webhook без IP-whitelist (можно подделать PAID), ACL на финансовые операции слабый, нет captcha. Готов план на 2 дня: whitelist + cookie fix + captcha + ACL (≈8 ч работы).

• **Финансы вслепую** — FocusPay работает в проде >6 сделок, но PnL **пустой**: ни topup, ни прибыль не зафиксированы. Личный расход ≈$33 за 2 дня виден, доход — нет. Критично: зафиксировать капитал внутри + накопленные комиссии на этой неделе.

• **Метрики ops отсутствуют** — нет dashboard по скорости обработки, очередям, времени на запрос. Эскалации теряются в чатах (нет SLA). Рекомендовано: `/ops/dashboard` с виджетами волюм/день + среднее время (автообновление каждые 5 мин).

• **MYVPN заблокирован на железе** — FR dedic (PAR-SM5038) не заказан, VPN-бот не задеплоен, prod-токены между FocusPay ↔ MYVPN не прописаны. Следующий шаг: заказать сервер **или** развернуть скелет бота на biz-хосте без трафик-ноды (account-linking заработает).

• **Ручная работа доминирует** — логи Telegram, кружочки, таблица Processing заполняются руками. Есть 3 quick win (effort S): скрипт export чатов в Days, git-hook для Processing INDEX, inline-команда `/task` в TG → авто-черновик задачи.

• **Техдолг процесса** — freeze-правило есть, но CI не валидирует diff на frozen-файлы; security-скан не блокирует merge; `tg_bot_btc` без git-истории (нет rollback). Offsite backup не настроен (локальная потеря данных критична).

## OpsReviewer

## OpsReviewer

### Сильное
- **Ops AI память + ежедневный диджест** — операторы получают автоматическую сводку в личку, контекст по людям/времени сохраняется в FAB (Done/Useful логируются).
- **Шаблоны CRUD + RBAC** — общая база ответов с контролем доступа по ролям; автор/версия/аудит логируются.
- **Self-check каждые 15 мин** (smoke + auth walls) — операторы заранее видят боли с курсами, калькулятором, банками (не ловят баги в лайве).
- **Multi-agent triage при create_dev_task** — проблемы сортируются по security/ui/backend, находки в `agents_json` видны оператору в `/x8/ai-tasks`.

### Слабые места (смены, скорость, эскалации)
- **Нет dashboard метрик по сменам** — не видно скорость обработки, время на запрос, очереди по операторам; "скорость" — только субъективно из чатов.
- **Freeze на финансы не гибкий** — при расчёте комиссии / скидки / кэшбека операторы ждут sync с backend; нет быстрого override для срочных сделок (влияет на конверсию BUY).
- **OWASP P1 открыты в проде** — guest cookie + ACL issues + отсутствие captcha создают риск для оператора (пока freeze защищает, но это костыль).
- **Эскалации теряются в чатах** — нет workflow escalation → supervisor; проблема может зависнуть (нет метрики SLA).

### Рекомендации (3 пункта, конкретно)
1. **Создать `/ops/dashboard`** с виджетами: пик → волюм/день, среднее время на запрос, очередь по статусам (pending/accepted/paid/disputed). Автоматом пополнять из логов chat_timestamps + order_status_log; обновлять каждые 5 мин. Фильтр по оператору/дате → выявить slow lane → коучинг.

2. **Маркировать "горячие" ошибки в шаблонах** — если self-check (каждые 15 мин) ловит одну и ту же ошибку >3 раза, автоматом поднять приоритет соответствующего шаблона в `/ops/templates` и пульнуть ping в групповой чат (#focuspay-ops). После fix → снять флаг.

3. **Настроить RBAC operatos_external для ручных override** — при крайнем случае (сбитый курс, банк висит) оператор может через `/ops/quick-fix` временно повысить комиссию/лимит *в одном запросе* (с логом + approval supervisor). Это не снимает freeze на файлы, но даёт гибкость на 30 мин.

## ProductAuditor

## ProductAuditor — FocusPay

### Риски

**Критические (производственные)**
- **OWASP P1 открыты**: guest cookie session hijack, finance ACL для admin ops, отсутствие captcha на критичных эндпоинтах, html.escape на referral/review — Ready for Production: **No**
- **Webhook без IP whitelist**: `WEBHOOK_ALLOWED_IPS` не задан, Payfast callback открыт на любой адрес — возможен fake PAID
- **Секреты могли светиться**: root-пароль, Lelouch credentials, bot token требуют ротации если были в логах/чатах
- **Offsite backup не настроен**: `OFFSITE_RSYNC` в `/etc/focuspay/backup.env` пуст — локальная потеря данных критична

**Средние**
- Freeze-зоны в проде без версионного тега — если случайно задеплоится изменение `order_financial.py` / `buy_payout_validate.py`, откат сложен
- Multi-agent Ops AI + self-check работают, но модель (`OPS_AI_AGENT_MODEL`) и false positive rate не указаны — риск шума
- Telegram digest ходит раз в день (час МСК) — delayed incident awareness

### Долг

**Архитектурный**
- `tg_bot_btc` без git init — нет истории, нет rollback при поломке бота
- Ops AI RAG whitelist расширен ad-hoc (handlers/routers/panel) — нужна явная политика «что индексируем»
- `focuspay-selfcheck` smoke + SAST без exploit attempts — покрытие неполное (нет фаззинга auth, нет load test webhook race)

**Код**
- BUY calc фикс 12.08 (округление fiat, курсы 503 fallback) покрыт unit-тестами (`test_buy_amount_contract.py`), но **интеграционный тест оператора buy-flow отсутствует**
- Шаблоны RBAC (author/is_system/version/audit) задеплоены, но строка `operator_external` ACL обрезана в CURRENT («формулы/Payfast не т») — неясно, завершён ли код
- `agents_json` миграция без downgrade path

**Процесс**
- FROZEN-правило в `.cursor/rules/frozen-domains.mdc` + `CLAUDE.md` §10, но CI не валидирует diff на freeze-файлы — можно случайно закоммитить
- Security-скан в CI (`scripts/security_scan.sh`), но результаты не блокируют merge — можно пропустить регрессию

### Приоритеты на 2 дня

**День 1 (высокий удар, низкая сложность)**
1. **WEBHOOK_ALLOWED_IPS + REQUIRE=1** — добавить IP Payfast в `.env`, перезапустить, smoke-test одной сделки (2 ч)
2. **Guest cookie P1** — `Secure; HttpOnly; SameSite=Strict` + TTL 15 мин (1 ч кода + 30 мин регресс)
3. **html.escape referral code / review text** — санитизация на рендере (30 мин + тест)
4. **Offsite backup**: прописать `OFFSITE_RSYNC=user@host:/backup/focuspay`, запустить вручную, проверить (1 ч)

**День 2 (оставшиеся P1 + stabilize)**
5. **Finance ACL для admin ops** — валидация `is_finance_owner()` в `POST /api/operator/orders/{id}/complete_manual` (1.5 ч + тест)
6. **Captcha на /api/public/order POST** — hCaptcha или Cloudflare Turnstile (2 ч интеграция + frontend)
7. **Интеграционный тест buy-flow оператора** — Playwright или Selenium + mock Rapira (3 ч, параллельно с captcha)
8. **Git init `tg_bot_btc`** + приватный remote, первый commit (30 мин)

**Отложить (>2 дня)**

**3. Пустой Processing/INDEX**
Таблица подготовлена, но записей нет. Значит, материалы (офферы, переписки) либо не обрабатываются, либо файлы создаются вне системы.

**4. Связь Days ↔ Circles**
Ссылки на кружки прописаны вручную в конце каждого дня. Нет автоматической агрегации по дате.

**5. Упоминания задач в переписках**
В логах 08-11 упоминаются «Админ отчеты», VPN, маркетинг, но задачи в TODO/Board не появляются автоматически — только если ты создаёшь вручную.

---

### Идеи автоматизации (effort S/M/L)

**S — Quick wins**

- **Telegram → Day sync (скрипт)**: Экспорт чатов через Telegram API → парсинг → append в `Days/YYYY-MM-DD.md`. Effort: **S** (Python + `telethon` / Bot API History).
- **Кружочки: авто-линковка**: При сохранении кружка в `Life/Circles/` — триггер добавляет ссылку в `Days/<date>.md` (inotify / cron + grep). Effort: **S**.
- **Processing INDEX: git hook**: При коммите новых файлов в `Processing/` — авто-добавление строки в таблицу (дата, имя файла, краткая тема из первой строки). Effort: **S**.

**M — Medium effort**

- **Алерт на ключевые слова**: Если в переписке «баг», «не работает», «фикс» → Telegram bot отправляет в админ-чат "создать задачу?" + inline-кнопка → автосоздание в TODO с линком на сообщение. Effort: **M** (bot + webhook + TODO API).
- **NLP-экстракт задач**: LLM-парсинг Days/YYYY-MM-DD → извлечение action items → draft в Backlog с тегом `#auto`. Effort: **M** (API Claude/GPT + промт).
- **Voice-to-text кружочков**: Автоматическая транскрипция (Whisper API) + сохранение текста рядом с аудио. Effort: **M** (сервис + storage).

**L — Large effort**

- **Единая панель Ops AI + Day context**: Ops AI при создании задачи автоматически ищет контекст в последних 3 днях Days/ + Processing/ → добавляет в `cursor_prompt` блок "Mentioned in chat: ...". Effort: **L** (RAG расширение + индексация Days).
- **Умный Processing inbox**: Входящие файлы (PDF-офферы, скрины переписок) → OCR + категоризация → автозаполнение таблицы + тегирование. Effort: **L** (OCR + ML classifier).

---

### Quick wins

1. **Скрипт `tg_export_day.py`** — раз в сутки (cron 23:55) выгружает сообщения за день из нужных чатов → append в `Days/<date>.md`. **Избавляет от копипаста переписок.**

2. **Git hook `.git/hooks/post-commit`** — при добавлении файлов в `Processing/` → автообновление `Processing/INDEX.md` (вставка строки с датой/названием). **Убирает ручное ведение таблицы.**

3. **Inline Telegram bot command `/task`** — ответить на любое сообщение командой `/task` → бот создаёт черновик в `TODO.md` с линком на сообщение. **Снижает барьер фиксации задач.**

### Следующий маленький шаг

**Заказать FR dedic PAR-SM5038** — разблокирует node deployment → можно поднять CP на biz-хосте → развернуть VPN-бота с заглушкой тарифа (оплата через Internal API к FocusPay).

Альтернатива (параллельно): задеплоить скелет VPN-бота на focuspay biz без трафик-ноды — account-linking + UI пополнения баланса работать будут, но без выдачи конфигов до появления node.

### Зависимости от команды

- **Решение:** заказывать ли сейчас FR dedic или отложить до фикса OWASP P1 в FocusPay.
- **Prod secrets:** `MYVPN_INTERNAL_TOKEN` + `FOCUSPAY_INTERNAL_TOKEN` для взаимных вызовов (генерация + запись в `.env`).
- **Валидация:** после деплоя бота — тест сценария «пополнение FocusPay → списание за VPN неделю → rollback на ошибке».
