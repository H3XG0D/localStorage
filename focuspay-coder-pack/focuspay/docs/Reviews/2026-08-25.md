## OpsReviewer

### Сильное

- **Инструменты под операторов готовы**: чат с шаблонами, shared RBAC-защита, Ops AI memory «запомни» для истории по людям/смакам.
- **Feedback loop работает**: оператор заметил ошибку в калькуляторе (BUY 0.5673 LTC) → быстро проверили, нашли баг округления и курсов → deploy же дня.
- **Self-check 24/7**: дефензивный дайджест в личку (15 мин smoke + nightly SAST) заигрывает потенциальные провалы до жалоб пользователей.

### Слабые места (смены, скорость, эскалации)

- **OWASP P1 всё ещё открыты** (guest cookie, finance ACL, captcha, referral escape) — если попадёт на оператора техподдержка по security-инциденту, будет беда; операторы не готовы к таким эскалациям.
- **Freeze-зоны без clear ops-гайдов**: финансовая логика закрыта для правок, но как оператор должен действовать если клиент жалуется на пayout? Нет SOP.
- **Метрики операторов невидимы**: нет данных про время ответа, количество нерешённых тикетов, repeat-issues по людям (только aggregate memory).

### Рекомендации (3 пункта, конкретно)

1. **Создай Security SOP для ops**: один-два сценария (A01 guest cookie = юзер видит чужую сделку, что делать / A03 finance ACL = оператор не может apply refund). Триггер: если P1 матчится, бот → `/x8/escalate` + assign SECURITY_OWNER.
2. **Введи дневной ops-чек-лист**: ежедневно в 8:00 — повторить 3 скрина (калькулятор, коры 503, ошибка payout validate). Автопроверка в `focuspay-selfcheck` + линк в дайджест → операторам спокойнее, меньше паника.
3. **Выцепи Top-3 операторов для A/B**: если есть данные (Days, People #focuspay-ops) — вот каким трём дай ранний доступ к `/ops/templates` v2 (более гибкие фильтры, история эскалаций). Остальным — недельку позже. Фидбек → улучшение инструмента.

## Риски

### Критичные (блокируют продакшн)
1. **OWASP P1 открыты** — Ready for Production: **No**
   - Guest cookie без SameSite/Secure → session fixation
   - Finance ACL в admin/ops не замыкает поля (referral_id escape, partner leak)
   - Captcha отсутствует на login/register
   - html.escape не везде (XSS в templates)
   - **Срок:** must-fix перед допуском пользователей

2. **Payfast IP whitelist отсутствует** (`WEBHOOK_ALLOWED_IPS`)
   - Spoofing webhook → произвольные COMPLETED статусы
   - **Срок:** 48 часов, иначе merchant может быть заблокирован

3. **Secrets в `.env` на проде могут быть светившимися**
   - `tg_bot_token`, `PAYFAST_*`, DB credentials
   - Если скопировались в логи/Git — ротация *сейчас*

### Средние (деградация)
4. **Freeze-домены без explicit approve в CLAUDE.md §10**
   - Риск: случайное изменение `order_financial` → целое число cashback вместо float
   - Регрессия: тесты `test_financial_safety.py` покрывают, но человек может забыть

5. **Интеграция MYVPN (E1) — federated billing недотестирована**
   - Internal API между FocusPay–MYVPN без rate limit/retry policy
   - Shortfall logic (крипто-счёт) — MVP slice 2, т.е. первое развертывание без этого

# AutomationScout — Отчёт

## Паттерны повторяющейся ручной работы

### 1. **Финансовый логирование** (Ledger + PnL)
- **Что:** вручную пишешь записи в формат `YYYY-MM-DD | type | amount | currency | ...`
- **Где:** [[Finance/Ledger]], [[FocusPay-PnL]] — журнал топапов, комиссий, расходов
- **Частота:** ~1–2 записи в день
- **Боль:** текстовые таблицы, нет SQL, невозможно запросить сводку или экспортировать

### 2. **Ops AI Memory — ручное заполнение** 
- **Что:** вводишь `запомни: имя=факт; время=…` в FAB; Done/Useful пишешь туда же
- **Где:** [[OPS_AI]] — нет видимого процесса автосборки из чатов/логов
- **Частота:** каждая сессия с людьми
- **Боль:** дублирование, может забыть записать, нет парсинга контекста

### 3. **Processing INDEX — вручная таблица пересылок**
- **Что:** таблица `Дата | Тема | Файл` — вручную заполняешь при пересылке
- **Где:** [[Processing INDEX]]
- **Частота:** каждая пересылка процессинга/офферов
- **Боль:** легко забыть заполнить; нет связи с реальными сообщениями

### 4. **Дневная активность** 
- **Что:** создаёшь файл `Day YYYY-MM-DD`, вручную добавляешь ссылки на кружочки
- **Где:** [[Day 2026-08-21]], etc.
- **Частота:** каждый день
- **Боль:** парсинг времени вручную; нужно помнить о создании дня

### 5. **OWASP Fix-план + ротация секретов**
- **Что:** список фиксов (guest cookie, finance ACL, captcha, html.escape); ротация паролей при утечке
- **Где:** [[FocusPay TODO]]
- **Частота:** нерегулярно, но risk-driven
- **Боль:** нет отслеживания статуса; секреты светились — нужна автоматизация

### 6. **Конфигурация инфры** 
- **Что:** руками задавать `WEBHOOK_ALLOWED_IPS`, `OFFSITE_RSYNC` в `/etc/focuspay/backup.env`
- **Где:** deploy docs (не видны в пласте)
- **частота:** при деплое
- **Боль:** ошибки конфига; нет валидации

### ⚡ **[M] OWASP Fix-план → CI/CD + auto-check + alert**
- **Что:** не ждать ручной ревизии P1 фиксов — вшей check в CI/CD + дневной алерт

  - Блокируй merge если `OWASP_FAIL=1`
- **Effort:** M (5–6 дней); Benefit: ежедневное напоминание, автоблокировка ошибок

### ⚡ **[S] Ротация секретов → automated script**

- **Как:**

  - Уведомление в админ-чат: `⚠️ Секреты ротированы в YYYY-MM-DD HH:MM`
- **Effort:** S (1–2 дня); Benefit: убирает 10 мин ручной работы, снижает human error

### ⚡ **[S] WEBHOOK_ALLOWED_IPS → валидация + auto-deploy**
