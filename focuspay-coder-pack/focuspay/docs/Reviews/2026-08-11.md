# Сводка отчётов для босса

• **FocusPay стабилен в продакшене, но нужна документация.** Финансовая логика заморожена и покрыта тестами, но требует extra-контроля при изменениях. Срочно: заполнить §7 в CLAUDE.md (серверные правила доступа) и инициировать git-миграцию — это база перед интеграцией с MYVPN.

• **Операционные метрики отсутствуют.** Нет таблиц смен, SLA, времени ответа по тикетам. Требуется завести Operations Log: еженедельная сводка по операторам (обработанные ордеры, среднее время ответа, инциденты).

• **MYVPN-интеграция готова к боевому тесту, один блокер.** E1-план готов, федерация БД реализована, VPN-бот в очереди деплоя — но требуется заполнить серверные правила FocusPay (§7 CLAUDE.md), без этого нет approval на продакшене.

• **Action на 2 дня:** (1) Ревизия TODO — актуализировать доску, (2) git init для tg_bot_btc, (3) заполнить CLAUDE.md §7, (4) добавить freeze-check в CI, (5) завести Operations Log.

## ProductAuditor

# ProductAuditor: FocusPay

## Риски

**Критические:**
1. **Репозиторий без git** — история коммитов не ведётся. При конфликте или откате потеряешь трудозатраты. **Решение срочно:** `git init` + приватный remote (уже в Backlog, но не выполнено).
2. **Секреты в `.env`** — при утечке нужна ротация (SECURITY.md указывает таблицу, но нет явного процесса повторной проверки). Рекомендация: периодический аудит доступов к `SECURITY.md`.
3. **Финансовая логика в FROZEN** — покрыта тестами (`test_financial_safety.py`, `test_financial_integration.py`), но 12 файлов сложной бизнес-логики (cashback, комиссии, лимиты). При багах в проде — прямой удар по прибыли. **Решение:** каждый изменение FROZEN требует явного approve (уже есть правило, но его нужно соблюдать).

**Операционные:**
4. **Интеграция MYVPN требует федерации БД** — две отдельные Postgres (FocusPay + MYVPN) будут синхронизироваться через API. Риск рассинхрона при сбое. ADR-007 есть, но реализация E1 — в процессе.

## AutomationScout

# AutomationScout: FocusPay + MYVPN

## 🔴 Паттерны ручной работы

### 1. **Финансовый ledger (Ledger + P&L)**
- **Что:** Ручная запись трат, комиссий, докидов в формате `YYYY-MM-DD | type | amount | currency | note`
- **Частота:** каждый раз при платеже / комиссии
- **Боль:** нет синхронизации с БД FocusPay → данные рассинхронены, риск ошибок

### 2. **Processing INDEX — ручное индексирование пересылок**
- **Что:** Вручную добавляешь строку `| дата | тема | файл |` для каждой пересланной истории
- **Частота:** по мере пересылок
- **Боль:** забываешь / лень → таблица не актуальна

### 3. **Board → TODO синхронизация**
- **Что:** "ревизия TODO и перенос актуального на доску" (пункт в CURRENT)
- **Частота:** периодически
- **Боль:** дублирование информации в 2 местах

### 4. **Day-файлы — копипаст из Telegram**
- **Что:** Вручную копируешь сообщения из чатов в `Days/2026-08-XX`
- **Частота:** ежедневно (или когда вспомнишь)
- **Боль:** много шума (уведы, рассеянные сообщения), неструктурировано

### 5. **CLAUDE.md заполнение (TODO-поля §7)**
- **Что:** "Заполнить раздел «Сервер» в CLAUDE.md"
- **Частота:** в начале каждого проекта / обновления
- **Боль:** ручной checklist, легко забыть поля

## 🎯 Quick Wins (S-effort)

### 1. **Freeze-проверка в CI**
```bash
# .github/workflows/freeze-check.yml или local pre-commit
if grep -q "services/order_financial.py\|services/buy_payout.py" <<< $(git diff --name-only);
then
  echo "❌ FROZEN файлы! Снять freeze фразой: --allow-frozen"
  exit 1
fi
```
**Результат:** никогда не запушишь freeze-нарушение случайно.

---

### 2. **Processing INDEX бот**
```python
# При пересылке в чат Processing:
# Бот парсит: дата сообщения, тему (первая строка), имя файла
# Добавляет в Processing INDEX автоматически

@bot.message_handler(content_types=['forwarded'])
def index_forward(msg):
    if msg.chat.id == PROCESSING_CHAT_ID:
        row = f"| {msg.forward_date.strftime('%Y-%m-%d')} | {extract_topic(msg.text)} | {msg.forward_from.username} |"
        append_to_processing_index(row)
```
**Результат:** Processing INDEX всегда актуален.

