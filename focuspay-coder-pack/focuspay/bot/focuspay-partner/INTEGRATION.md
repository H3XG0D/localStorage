# Промокоды и связка с обменником Focus Pay

## Как работает промокод
1. На первый принятый ролик автора обменник FocusPay создаёт настоящий купон: скидка 200 ₽, 100 активаций, обмен от 3 000 ₽. Код на баннере до этого момента в обменнике ещё не действует.
2. Режим в админке партнёрки по-прежнему может быть «скидка сразу» или «кэшбэк на второй обмен» для ручной проверки оператором. Деньги на заявке списывает обменник по купону `exchange_discount`, не эта SQLite.
3. Активации кончились — клиенту отвечает бот: «напишите оператору», дальше оператор договаривается сам.
4. Автор берёт новый код в «Материалах»: только после первого принятого ролика, не чаще раза в 3 дня
   (если текущий не разобрали), и не больше 2 живых кодов одновременно. Баннеры пересобираются с новым кодом.
5. Все правила проверяет бот партнёрки и отвечает «можно» или «нельзя + причина».

Правила (цифры меняются в админке): только новый клиент; один раз на человека и на одни реквизиты;
свой код автора не работает (сверяются и аккаунт, и реквизиты, на которые автор выводит деньги);
дневной лимит на код; при всплеске код сам встаёт на паузу; месячный бюджет кэшбэка;
кэшбэк не выдаётся, если код автора за это время поставили на паузу или автора забанили.

Почему кэшбэк, а не скидка: ферма аккаунтов делает по одному обмену и ничего не получает,
бонус забирают только те, кто реально вернулся.

## Способ 1 — без программиста: панель оператора
1. Админка → Ещё → «Админы и операторы» → добавить оператора по Telegram ID
   (оператор узнаёт ID командой /myid в партнёрском боте). Ему придёт кнопка «Проверка промокодов».
2. Клиент назвал код (первый обмен): вкладка «Новый клиент · код» → код, клиент (@username или ID), сумма,
   реквизиты клиента (куда отправляем) → «Проверить» → «Засчитать код». Скидки на этот обмен нет.
3. Второй обмен: вкладка «2-й обмен · кэшбэк» → клиент, сумма, реквизиты → если кэшбэк есть — «Применить»
   и сделать клиенту скидку 200 ₽.
4. Обмен прошёл — «✅ Обмен проведён». Не состоялся — «↩ Отмена».
Без «Проведён» кэшбэк клиенту не откроется; незавершённые заявки сгорают через сутки.

## Способ 2 — программист бота обменника (API)
Все запросы: POST {PARTNER_URL}/api/..., заголовок X-Track-Secret: {TRACK_SECRET}, тело JSON.
PARTNER_URL — адрес партнёрки на сервере, TRACK_SECRET — из /opt/focuspay/.env.
payer — реквизиты клиента (карта/телефон/кошелёк) как есть: партнёрка хранит только отпечаток.

| Когда | Запрос | Тело |
|---|---|---|
| Клиент ввёл промокод | /api/promo/validate | {"code":"VOVA7K","client_id":123,"amount_rub":5000,"payer":"2200...","is_new":true} |
| Создана заявка с кодом | /api/promo/apply | то же + "order_id":"A-100" |
| Второй обмен: есть ли кэшбэк | /api/promo/cashback/validate | {"client_id":123,"amount_rub":4000,"payer":"2200..."} |
| Применить кэшбэк | /api/promo/cashback/apply | то же + "order_id":"A-200" → в ответе discount |
| Заявка завершена | /api/promo/complete | {"order_id":"A-100","amount_rub":5000,"profit_rub":120} |
| Заявка отменена | /api/promo/cancel | {"order_id":"A-100"} |

Ответ: {"valid":true|false,"reason":"client_used","reason_text":"Этот клиент уже использовал промокод","discount":0,"cashback":200}.
reason_text можно показывать клиенту как есть. Повтор apply с тем же order_id безопасен.

Необязательно, для статистики по ссылкам авторов:
- /start по ссылке t.me/focuspay1_bot?start=p_VOVA7K_tt → /api/track {"event":"start","client_id":123,"start_param":"p_VOVA7K_tt"}
- любой завершённый обмен → /api/track {"event":"exchange","client_id":123,"amount_rub":15000,"profit_rub":300,"order_id":"A-100"}
